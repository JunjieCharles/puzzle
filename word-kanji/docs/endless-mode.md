# 无尽模式规划

更新日期：2026-10-02。状态：原网页版已实现一字、二字无尽模式，尚未执行线上部署。保持纯静态部署，浏览器 Worker 直接生成；以下区分用户确认的规则和当前实现默认。Toy 平台仍不开放无尽模式。

## 已确认需求

- 顺序具有随机感，但所有玩家的同一模式第 x 关相同，不随设备、时间、作答或跳关而改变。
- 一字、二字模式独立生成、独立编号、独立进度、独立冷却；两模式之间可以出现相同答案字。
- 某字在第 n 关答案中出现后，第 n+1 至 n+100 关的答案均不得包含该字，第 n+101 关起才可再次使用。二字按每个字判断，不区分左右位置。
- 用户已确认冷却只限制答案中的字，不限制后续题面的提示字。
- 用户明确无尽模式每关不需要选取最难的几个线索词，也不要求为每个答案寻找最难题面；保留组词合法、全题互异和扩展词库唯一解等质量规则。
- 希望不依赖预生成题库，避免生成和保存超大题库。通用词库仍用于中文合法性与唯一解检查。
- 本轮仅实现原本的网页版，暂时忽略 Toy 平台。
- 不允许跳关。每种模式仅保存序列版本与下一道待完成关号，不保存通过题号列表；必须答对当前关才能前进。
- 采用浏览器直接生成。允许生成时在内存中处理答案与冷却状态；仓库、发布文件、存档、缓存和日志不保存真实题目的明文答案或其可逆编码。不考虑防止开发者工具提取与重放。

## 当前浏览器生成实现

采用“固定版本的通用词库 + 确定性生成器 + 最近 100 关冷却状态”，按需构造题面；不从闯关题库抽题，也不先枚举全部线索组合。

`public/endless-engine.js` 实现运行时方向词库索引、确定性抽样、全题互异和扩展词库单解检查；沿用 `generator.py` 的质量规则，不读取闯关题集。`scripts/export_endless_lexicon.py` 仅导出完整通用 HSK 单／二字词与扩展词库，生成的公开词库大小为 695,603 字节，不随关数增长。审计逐项比较完整源词库，拒绝用题目专属候选表替代。

每个模式固定独立的序列身份：词库快照、规则版本、生成器版本与种子。对通用字词按明确的 Unicode 顺序规范化；随机算法、整数操作、抽样方式及候选遍历顺序均固定，不能依赖集合遍历、系统时间或默认随机库的隐式行为。

生成第 x 关时：

1. 从该模式之前最多 100 关的答案字集合形成禁用集合。该状态按关号推进，不按玩家实际完成情况推进。
2. 按固定伪随机顺序遍历合格候选答案，排除含禁用字的候选；二字还须整体成词。
3. 从通用词库的方向索引组合提示字。答案及全部局部词属于 HSK 1–6、7–9 范围；全题汉字互异；在固定的完整扩展词库和字域内检查唯一解，不能因为备选解含重复字就将其忽略。
4. 接受第一道通过质量检查的题，更新冷却状态。当前默认每个候选尝试 64 次随机线索；全部候选尝试失败后才按同一候选顺序执行完整线索搜索，不比较难度。候选尝试次数属于协议，不因机器快慢改变；按“固定种子、版本、模式、关号”派生随机流，尝试按固定顺序消耗随机数，避免请求顺序干扰结果。
5. Worker 只向页面返回独立公开 ID、题面、盐及题目绑定摘要，消息另有请求编号和恢复进度；生成答案不跨 Worker 边界发送。ID 和盐由版本、模式与关号的 SHA-256 派生，均不编码答案、内部词条 ID 或候选下标。

序列版本为 `endless-v1`，固定种子标识为 `seed-2026-10-02`。种子展开使用 FNV-1a，随机算法使用显式 32 位运算的 Mulberry32；候选使用 Fisher–Yates 洗牌，字词按 Unicode 码点排序。词库加载时校验 SHA-256 `430a352eca23b62195f7a536fd2e79651b4d8b2fb663eab6b88581a66b3be44f`，不匹配则报错，不能用不同词库悄悄恢复旧进度。判题摘要的前缀分别为 `endless-v1-1`、`endless-v1-2`。

用户已确认无尽模式不执行闯关的最难线索／最难题面筛选；按固定随机顺序选到合格题面即可，不遍历全部题面比较难度。“全题库答案字不重复”和跨题线索词去重也不直接套用到无尽模式。当前建议随机难度，不要求每关越来越难；未来难度分布若影响选题，也必须纳入序列版本。

## 冷却、可持续性与重复

一字至少需要 101 个可用答案字；二字在当前答案两字互异规则下，任意连续 101 关需要 202 个不同答案字。这些只是必要条件，尤其二字的合法词语配对及可生成唯一题面仍可能造成死路。

`scripts/check_endless.mjs` 在当前固定通用词库上，运行时确认至少有 101 个不同单字和 201 个彼此汉字不相交的二字词，各自能生成合格题面。最近 100 关最多禁用 100／200 个字，每个禁用字最多排除上述互不相交集合中的一个成员，因此至少仍有一个可用候选。这结合完整线索搜索，保证当前固定词库不会仅因冷却而耗尽；不构成任意词库或搜索延迟的保证。验证只输出数量，不保存实际候选或题面答案映射。

固定重试预算耗尽不等于数学上无解，当前实现随后进行完整线索搜索。不得按请求时间随机换题、缩短冷却窗口或降低唯一解要求，已公开的关卡不可回溯修改。若词库或算法变更导致候选耗尽，应明确报错；人工词表测试覆盖此情形。完整搜索存在最坏情况耗时，不能仅凭容量证明承诺恒定响应速度。

“无尽”当前建议解释为持续提供关卡，允许冷却结束后复用答案及题面，不承诺永不重复。固定有限词库、有限布局下，不重复题面的严格无限序列不可能存在。更长的同题冷却若另行增加，需要纳入调度规则，不能默默追加全历史去重。

## 已确认的部署与答案保护边界

保持原网页版纯静态部署，发布固定版本的通用词库、通用算法及独立选定的固定种子，不增加生成服务，不发布预生成的完整题库。公开种子用于确定随机过程，不能用于编码预先选定的答案序列；不得以答案下标表或特殊词表代替明文答案表。

当前使用模块 Web Worker，串行推进每个模式的规范序列，完成选题和唯一解检查后只发送白名单题面记录。答案只在生成所需的内存中处理；每模式冷却队列保留最近最多 100 关的必要答案字，过期后释放引用。不记录答案日志，不写入 localStorage、IndexedDB、Cache API、service worker 缓存、存档码或历史状态。不承诺 JavaScript 内存可被立即物理擦除。

题目绑定的加盐摘要用于判定玩家输入，摘要及题面应可随关号重建；影响题面选择的随机流与校验元数据分离。开发者工具仍可截取运行时数据或重放生成过程，用户已明确本轮不考虑此类防护，不宣称严格保密。

当前实现刷新后从序列起点重放，不能只用第 x 关的种子跳过前序。每模式在 Worker 内保留当前滚动状态和最近一题的公开记录，不保存全历史题目或额外检查点。答案字、答案候选下标或可逆编码的冷却检查点都不能作为持久化恢复捷径。每推进 32 关向页面报告恢复进度并让出 Worker 事件循环，允许离开页面取消恢复；取消不会改变后续生成规则。更高效的分段／可随机访问调度尚未实现。

词库索引与固定大小的滚动状态不随总关数增长，重放时间随关号增长。桌面 Node 20 测试生成至第 10,000 关，一字约 0.5–0.6 秒、二字约 3–4 秒，包含检查的运行略有波动；不能代表真实手机性能。实际静态发布包的桌面 Edge 测试中，第 10,000 关恢复约为一字 2 秒、二字 6 秒，刷新前后题面相同；浏览器加载、让出事件循环和测试开销也计入其中。当前只在答对后的停留期间提前准备下一题的公开记录，不持久化，也不批量预取；未进行真机移动端测速。

### 内存丢失后的序列一致性

内存中的冷却队列是固定序列的可重建状态，不是决定序列的唯一原始数据。刷新、关闭页面或 Worker 被终止后，读取存档的序列版本、模式和关号，以相同词库、种子和算法从起点顺序重放，恢复目标关之前最多 100 关的冷却状态，再生成目标关。重放只做生成计算，不要求玩家重新作答，也不更改已保存进度。

不能从目标关号搭配空冷却队列直接继续，也不能认为只重算前 100 关就足够：这 100 关本身依赖更早的状态。当前方案从起点重放，或接续本次会话仍有效的滚动状态。若词库或旧版生成器不可用，提示无法恢复，不得静默换成新版本。

只要完整固定所有影响结果的输入和操作顺序，重放应与不中断连续生成完全一致。耗时预算、浏览器速度、Worker 调度或用户作答不能改变候选选择；暂停后必须恢复原计算，不能按超时跳过候选。取消最难线索筛选可减少每关搜索工作，但不能消除顺序重放的成本，具体延迟仍需验证。

验收必须比较连续生成与刷新／Worker 重建后的目标题面及后续序列，并覆盖 100 关窗口边界、两模式交替和预取取消。使用人工词表测试，真实词库测试只输出一致性与性能汇总，不输出答案。

## 页面与版本（当前实现默认）

- 首页 → 无尽模式 → 一字／二字 → 从当前关继续；显示“无尽 · 第 x 关”，不展示虚假的总关数或通关终点。
- 答对后的 900ms 停留、自动切关、输入行为沿用当前答题页。用户已确认不允许跳关；当前不提供选关、回看、答案揭示或总进度条，不继承闯关的通过数加三解锁规则。显示已通过关数。
- 2026-10-02 过关动画修正：过关条仍为 900ms，通常在 700ms 开始淡出、再过 200ms 直接切入已准备好的下一题，不插入空白棋盘或“准备题目”闪帧。若下一题生成较慢，保留玩家刚填的字与成功反馈，准备好后再用 200ms 淡出；进度条填满后保持。离开页面会取消待切关操作，生成失败则沿用下一关的错误提示与重试入口。
- 同日用户明确问题是过关条缺少动画。现在各模式共用同一启动函数和时间常量，每次答对重建填充元素确保从空重播，离开页面时统一隐藏。即使系统开启减少动态效果，900ms 过关条也保留；仅装饰性的棋盘动画被关闭，详见页面设计需求。
- 路由为 `#endless-types`、`#endless-one`、`#endless-two`，答题入口始终恢复下一道待完成关；手工添加关号后缀不会跳关。浏览器后退、重新进入同样不能改变应答关号。
- 存档隔离闯关与无尽、一字与二字，仅保存 `revision: endless-v1` 和 `next`（下一关，从 1 开始）；不保存输入、正确答案、通过列表或答案冷却队列。模式名为 `endless-one-standard`、`endless-two-standard`，本地键为 `word-kanji:<模式名>:v1`。文本存档沿用 `HT101-2`；旧码缺少无尽记录时保留本地进度，同版本导入取较大的下一关关号。只导出已有通过进度的无尽模式。
- 同一模式保持一条固定序列；发布后不替换旧关。影响结果的词库与算法更新应建立明确的新序列版本并保留旧版恢复能力，不能仅更新种子导致同关换题。当前仅支持 `endless-v1`，未知版本拒绝读取或导入。关号使用 JavaScript 安全整数，最大允许值为 `Number.MAX_SAFE_INTEGER - 1`，不宣称超出数值范围仍可无限编号。
- 普通网站继续兼容 `/puzzle/word-kanji/`，进度沿用网页版本地存档与文本存档码体系扩展。Toy 平台不在本轮规划范围内。

## 验证入口与未开放范围

- `python -X utf8 -m unittest discover -s word-kanji/tests -v`：含 Node 人工词表测试，检查 100 关窗口、二字跨位置冷却、输入词表顺序无关、重放、重复字备选解、候选耗尽、完整搜索兜底及存档。
- `node --experimental-default-type=module word-kanji/scripts/check_endless.mjs`：运行时容量证明、两模式各 10,000 关冷却及重放一致性；抽样用独立直接枚举复核唯一解，仅输出汇总。
- `python -X utf8 word-kanji/tests/browser_endless.py --url <预览地址>`：人工词表下的过关、禁止跳关、刷新、模式隔离、存档、加载失败重试及取消重放；截图仅含人工题，位于仓库外临时目录。
- `python -X utf8 word-kanji/tests/browser_advance.py --url <预览地址>`：四种模式连续过关的实际填充比例递增与每关重播，覆盖普通及减少动态效果两种浏览器偏好；不只检查过关条可见性。
- `python -X utf8 word-kanji/tests/browser_endless_release.py`：临时构建白名单发布目录，在 `/puzzle/word-kanji/` 检查实际词库和 Worker 加载、无尾斜杠入口、深关恢复和刷新一致性。
- `python -X utf8 word-kanji/scripts/audit_public.py`：新增通用词库完整性检查，仍需人工复核自由文本与所有前端持久化写入；有限扫描不构成任意泄漏形式的完整证明。
