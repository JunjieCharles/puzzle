# 文本存档码

入口位于帮助按钮左侧。导出码可直接发送到另一台设备，再粘贴导入；不需要账号。打开存档弹窗不会暂停自动切关，只有执行有效导入时才切到选关页。复制失败时可手动选择文本复制。

## 当前格式

`HT101-1.<Base64URL JSON>.<16 位十六进制校验码>`

JSON 包含协议版本 `v: 1`、每次导出重新生成的 128 位随机 `nonce`、按模式名称组织的 `modes`。当前仅支持 `campaign-one-standard`，其记录包含 `revision`（题集版本）和 `completed`（已通过关数；0 表示从第 1 关开始）。不含玩家输入、答案、完整组词、设备身份或认证信息。

校验码是前两段（含分隔点）的 SHA-256 前 16 位十六进制字符，用于发现复制错误，不是签名或防作弊机制。Base64URL 仅作文本编码，不是加密。随机值用于使相同进度的导出码不同，不代表玩家身份。

## 验证与导入

- 接受复制时产生的空白和换行，限制输入长度为 65,536 字符。
- 校验协议版本、JSON 格式、随机值、摘要、已知模式的记录；进度必须是非负安全整数，当前模式还不得超过当前题集关卡数。
- 当前模式题集版本必须匹配。跨题集仅按关号恢复可能对应不同题目，因此不自动套用；失败时不更改当前存档。
- 当前默认按较高进度合并，旧码不会使本地进度倒退；成功后立即尝试写入现有 localStorage 存档并进入选关页。写入失败时可继续本次游戏，同时提示用户保留文本码。
- 当前浏览器已有存档无需迁移，导出直接读取现有进度。普通过关仍沿用原本的本地存档机制。

## 后续增加模式

模式名称固定且不可换义，例如将来二字型应使用另一个独立名称。扩展解析器和对应模式的进度存取时，继续读取版本 1 的既有一字型字段；缺少的新模式记录表示没有已保存进度，新玩家从零开始，已有本地进度不清除。

增加可选模式不需要提升协议版本，也不能要求旧码包含新模式。当前解析器忽略未知模式，不保存或重新导出它们；不承诺旧客户端完整读取新客户端存档。若未来有不兼容的格式变化，再提高版本并保留旧版本解析和迁移入口。

导出时可只写已有进度的模式；导入时逐个验证本版本支持的模式，并在全部验证通过后合并应用。当前仅实现一字标准型，未预建二字型或无尽模式存档。
