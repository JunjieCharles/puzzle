# 闯关页面设计需求

本文件记录当前有效的产品需求和交互约定。游戏规则见 [规则定义](wadou-kaichin-rules.md)，数据边界见 [公开与私有边界](public-private.md)。后续设计调整必须同步更新本文件。

2026-10-02 新增 Toy 独立版本，以下存档码及 localStorage 说明仍针对普通网站。Toy 版进入自动读取、过关自动保存平台内云存档，无手动连接/保存步骤，不与普通网站互通；一字、二字独立按通过数排名，同分先达成者优先。独立入口、账号恢复、离线与排名时间口径见 [Toy 版本计划](toy-plan.md)。玩法与题库仍共用。

Toy 专属工具区：右上角为排行榜图标与帮助按钮，原存档按钮直接替换为排行榜入口，云存档状态常驻在两枚按钮下方；不再提供云存档弹窗或首页重复入口。普通网站的存档按钮及文本码保持不变。

## 用户明确的需求

- 仅主界面上方显示较大的铜钱 logo 与「中文和同101」标题；题型、选关、答题及通关页面均不显示网站标题栏。

- 静态网站，访问路径为 `/puzzle/word-kanji/`，保留最简基本功能。
- 首页选择「闯关模式」或「无尽模式」；无尽模式暂未开放。
- 闯关模式选择「一字标准型」或「二字标准型」，均已开放。
- 题型卡片使用题目结构图案替代「一」「二」汉字图标：空心格表示待填字，外围实心小块表示题面字，仅使用向右、向下箭头；一字型为单中心十字布局，二字型为两个横向相连的待填格，各有上下线索。图案不含真实题面或答案，保留题型名称，已开放题型不显示未开放标记。
- 点击任一已开放题型先进入独立选关界面，再进入题目。
- 二字标准型已替换为 311 题，答案中的任一汉字不论位置在二字题库合计最多出现一次，允许与一字答案重复汉字。一字及二字题库按“词语＋待猜位置”去重，同一个 AB 猜 A 和猜 B 可分别使用。筛选和排序参考一字标准型，不改变一字题库文件、版本号及进度。
- 一字标准型使用 586 道闯关题，包含 HSK 7–9 级；原 587 道筛选题中移出一道专供帮助演示。
- 从易到难排列，相同答案只保留最难的一题。
- 难度按四个题面字在对应词首或词尾可组成的二字词数量评定，计数采用更大的词库；将四项计数从小到大排序，再按字典序比较，越大越难，不求和。
- 每个答案取难度最高的题目；这一关卡筛选限制不属于良好题目的标准，替代此前保留多题再排除重复线索词的选关策略。
- 一字型填空区自动只保留一个字。二字型支持直接输入或粘贴整个词，按从左到右分填两个空格，无需逐格点击；空格不显示圈号占位符。
- 切换到下一关后可以直接输入，不需要再次点击填空区。
- 主页面不添加玩法说明、词库来源等解释性文字；通过右上角圆形问号按钮打开帮助，以非现有关卡的专用例题简短说明玩法。
- 网站名称和标签页标题使用「中文和同101」。页面标志及标签页图标共用铜钱 SVG；闯关模式使用旗帜图标。移除右上角「字谜」及「选择模式」上方重复的「和同開珎」，入口不使用斜向箭头。
- 返回入口统一为内容区顶部左侧的醒目圆形左箭头按钮，与右侧存档、帮助按钮保持同一高度，横竖屏均适用；正文预留顶部空间，避免遮挡。不显示「返回」「选关」等文字，保留无障碍名称；题型、选关、答题和通关页面采用同一样式。关卡进度文字加大并增强对比度；移除选关页和答题页的「继续闯关」入口。
- 页面随窗口宽高自适应，减少过多留白，在常见桌面和手机尺寸下尽量无需滚动；在简约的米白、绿色风格中增加游戏感。
- 界面字号保持均衡，避免大标题与细小标签、按钮文字形成过大落差。
- 过关后保留玩家刚填的字，成功效果不能遮盖或清空当前填字；切换关卡或离开页面时再清空。
- 「过关」反馈和主操作按钮文字需足够醒目，反馈与操作区之间留出清晰间距；操作区靠近面板底部，避免下方留白过多。下一关现已改为自动跳转。
- 答对后无需再次点击下一关，短暂停留并过渡后自动进入下一关；不能瞬间切换，仍需看清刚填的字和过关反馈。
- 提交按钮增大点按区域，优先方便手机触控。
- 返回、选关及分页等按钮也扩大触控区域，手机端减少关卡网格列数并增加间距。
- 横屏与竖屏使用一致的按钮最小高度和字号，不因横屏变宽而缩小触控控件。
- 仓库及前端不保存真实题目的明文答案，提交前检查。

## 当前实现默认

以下为满足需求采用的当前实现选择，并非用户逐项指定的规则。

### 二字题库与模式隔离（2026-09-11）

- 筛选沿用六个外侧线索的方向组词计数序列，最大题数优先，再按原计数序列选取最难题面。排序单独采用用户指定的两步难度：每步线索计数取最小，每种填字顺序取两步最大值，整题取两种顺序的最小值；同分再比较原六项序列及规范键。公式和方向见[二字难度](two-difficulty.md)，筛选细节见[二字题库](two-standard-count.md)。
- 两个输入格从左到右连接，不显示圈号占位符。输入法组合期间不截断，选词完成后将二字词分填两格，提交时按从左到右拼接校验，切关后聚焦第一格。当前默认：在任一格输入或粘贴两个及以上 Unicode 字符时，取前两个字符覆盖两格；单字输入只修改当前格，正常输入保留当前焦点，不自动提交，玩家仍可逐格修改。第二格有字时退格正常删除当前字；第二格已为空时再按退格，删除第一格的字并聚焦第一格，支持键盘及移动端向后删除事件。输入法组合期间、过关或回看只读状态不触发跨格删除。过关动画、解锁、分页、回看及隐藏答案沿用一字模式。
- 一字路由 `#levels`、`#play/<关号>`、`#complete` 保持不变；二字使用 `#levels-two`、`#play-two/<关号>`、`#complete-two`，支持刷新、返回及从题型入口切换。
- 一字新 localStorage 键为 `word-kanji:campaign:v2`，二字为 `word-kanji:campaign-two:v2`；继续读取并保留各自的 v1 键。两个模式分别保存题集版本、实际通过数和已解锁范围内未通过题号，不保存输入或解答。
- 文本存档导出使用协议 2，继续接受协议 1；一字、二字模式独立记录实际通过数和已解锁范围内未通过题号。导入前验证全部已知模式，再合并已通过题目。旧码缺少二字记录时不影响已有二字进度。只有一字记录的旧码可在二字页面导入，导入后进入一字选关页。
- 二字回看按需加载完整通用 HSK 二字词表，匹配该题的加盐摘要；词表不按题目建立关联，求得的答案只在当前页面运行时显示，离开或隐藏时清除。
- 无尽模式仍未开放。
- 2026-09-11 用户确认发布二字标准型，首发版本为 `d50323fe85aaf35b`，首发前开发期旧版本不处理存档迁移；后续换库须重新评估兼容。一字题库和版本不改，原 localStorage、文本码及已有一字迁移例外继续支持。
- 二字输入支持左右方向键切换：第一格按右键进入第二格，第二格按左键返回第一格，空格和已有字的格子均适用。当前默认切换后选中目标格文字以便修改，不改动填字、不自动提交；最外侧不循环切换。输入法组合期间、带修饰键、过关或回看只读状态保留按键原有行为。

### 选关与进度

- 后续需求：部署到 GitHub Pages 后，玩家存档应尽量长期保留，减少更新网站或题集造成的进度丢失。
- 已实现文本存档码导出／导入，入口为帮助按钮左边的圆形存档按钮。导出生成可复制的文本码；复制受限时保留可手动复制的文本。导入只恢复进度，不保存答案，也不做身份验证。
- 当前分别保存一字和二字标准型的实际通过数、已解锁范围内未通过题号、题集版本，文本码加入随机值与校验码。同一进度每次导出会得到不同存档码。导入前验证格式、校验码、全部已知模式的题集版本及关卡范围；合并已通过题目的并集，成功后显示选关页。保存受限时明确提示仅在本次游戏生效。
- 兼容方向为新版本读取旧存档：模式以独立名称记录，将来新增模式时，旧存档缺少的模式按零进度处理（已有本地进度则保留）。不要求旧版本保留未知模式数据。协议与扩展约定见 [存档码](save-code.md)。
- 尚未实现通用跨题集迁移或云端同步。明确例外仅为一字移除原第 197 关的进度迁移，本地存档和文本码都适用。二字开发期不实现旧版本迁移，其他题集更换不按原关号强行套用。静态托管本身不提供玩家云存档。

- 每页关卡数随网格可用宽高调整，支持上一页、下一页及关卡范围选择；窗口变化后保留原页首关卡所在的新分页。
- 每次进入选关页（题型入口、答题页返回、刷新或导入存档后），默认定位到最新已解锁关卡所在页；全部通过时定位最后一页。一字、二字均适用，进入后仍可手动翻页。
- 一字和二字均解锁前 `min(总题数, 实际已通过题数 + 3)` 题，初始解锁三题。解锁范围内可自由选题，已通过题可重玩，重复通过不增加通过数。通过最后一题但仍有其他未通过题时不算全部通关。
- 当前默认：过关后前往后方第一道已解锁且未通过的题；后方没有则回到最前面的未通过题，全部通过才显示通关页。未通过题也显示「下一关」按钮，可在已解锁范围内切题；回看答案仅限真正已通过的题。
- 选关页标记已通关及当前待完成关卡，通过关卡按钮进入。
- 答题页可返回选关或进入上一关；回到当前闯关进度时在选关页选择相应关卡。
- 已通关关卡提供「查看答案」按钮，未通关关卡不显示。查看后在中央格显示答案，不自动切关、不改变进度；导航时清除结果。当前默认按需在浏览器中枚举通用汉字并匹配现有校验摘要，计算期间显示「查看中…」，离开页面取消；不预埋或持久化标准答案。
- 查看答案后，下方依次显示「上一关」「隐藏答案」「下一关」。隐藏会清空中央格并恢复可输入及「查看答案」状态；下一关替换当前导航记录，不新增返回层级。当前默认最后一关的「下一关」禁用，三个按钮在窄屏保持同一行、触控高度至少 44px。
- 查看与隐藏答案保持组件位置不变：提交按钮隐藏时保留原占位，反馈区预留行高，下方操作固定为三列，「查看答案／隐藏答案」共用中间位置。隐藏时不重播入场动画、不主动弹出键盘。
- 关卡地址使用 `#play/<关卡编号>`；刷新指定关卡仍停留在该关，未解锁或无效编号返回选关。
- 从首页正常进入时，手机／浏览器返回键按「答题或通关 → 选关 → 题型 → 首页」退回；自动切关及「上一关」替换当前历史记录，不新增层级。页面圆形返回按钮优先退回已有上级记录，避免重复堆叠。刷新保留导航历史；直接通过链接进入时不伪造先前访问记录，系统返回键保留浏览器原生行为，页面返回按钮仍可进入上级页面。历史状态只保存路由，不含输入或答案。
- 全部通关后显示奖章、「恭喜，全部通关！」和完成数量，不提供重新开始或重置进度入口；仍可返回选关复习。
- 本地仅保存题集版本、实际通过数和已解锁范围内未通过题号，不保存玩家输入或标准答案。新进度写入独立 v2 键，原 v1 键保留；旧进度按前 N 题已通过读取并合并。重复导出相同题集保留版本；题集实际变化时需要明确的迁移规则。
- 跨标签页在保存、页面导航、导出和导入时读取本地进度并合并已通过题号，不监听其他标签页的实时变化。当前默认使用浏览器写锁（可用时）串行保存；不支持写锁时采用读取后合并再写入，极端同时写入仍可能存在竞争。
- 保存失败时持续显示简短提示及导出入口，允许继续游戏；后续保存成功时隐藏提示。

### 输入与判题

- 帮助按钮沿用返回按钮的 64px 深绿圆形样式，位于页面内容区右上角。弹窗展示一个填字与四个顺箭头组成的词。按用户要求，将原第 197 关改为公开教学例题并从闯关题集中删除，替换此前独立编写的例题；导出器排除该题及同题位置互换。教学内容不绑定公开关卡 ID、校验摘要或进度，原私有筛选数据保留作历史资料。
- 帮助可通过关闭图标或 Esc 关闭，与自动切关独立；打开或关闭帮助均不暂停、重置或触发过关计时。后台照常切到下一关或通关页，帮助保持打开直至主动关闭。帮助本身不修改输入或进度，正常切关仍清空上一关输入。

- 多字输入保留第一个 Unicode 字符，扩展区汉字不被拆成两个字符；中文输入法在选字完成后截取，不打断拼音组合过程。
- 进入或切换关卡后自动聚焦填空区；支持按钮提交和回车提交，输入法组合期间不提交。
- 非单个汉字给出输入反馈，错误答案允许重试，正确答案显示过关并开放下一关。
- 二字提交按整词判定：答案错误或输入不完整时，两格一起标红，不提供逐字对错提示；错误状态下的焦点光圈也使用红色。修改任一格时一起清除两格错误标记，重新提交后再判定。
- 判题采用题目绑定的加盐 SHA-256 摘要；成功后将输入设为只读，保留玩家当前填字，以边框、底色和独立状态文字提示成功。切关、返回或离开页面时清空输入，不预置标准答案或把输入持久化为答案缓存。
- 当前默认成功停留 700ms，再用 200ms 淡出过渡，总计 900ms 后自动进入下一关并聚焦输入框；过关进度动画同步为 900ms。最后一关自动进入通关页。过渡期间防止重复提交；返回选关或离开页面会取消待执行的自动跳转。
- 移除手动下一关按钮，在原操作区显示短进度动画，保持布局稳定；偏好减少动画时保留相同停留时间，取消淡出、位移及进度动画。
- 加载失败可以重试；本地存储不可用时仍可在当前会话内游玩。

### 排序与页面

- 扩展计数词库采用 HSK 全等级与 CC-CEDICT 的二字词并集，按字面去重。上、左题面字统计作词首的数量，下、右统计作词尾的数量；无需再按答案字域或题面互异性排除词条。
- 一字型四项计数升序排列后的字典序作为唯一难度依据，同难度以原始题目编号决定先后；HSK 等级仅保留作统计。完整定义见 [难度评定](difficulty.md)，二字型六项扩展及同分策略见 [二字题库](two-standard-count.md)。
- 每个答案只保留一题，一字型同难度时默认选原始题目编号最小者，二字型使用确定性的线索规范顺序。关卡按难度升序排列；旧版同答案间隔策略不再需要，旧私有题集仍保留。
- 使用简洁的单页布局，适配桌面及手机；未开放的入口不可点击。
- 桌面使用较宽的游戏面板，棋盘根据可用高度缩放，矮横屏将棋盘与提交区并排。选关自动控制行列数，避免固定关卡数量挤出滚动条；极小视口或放大文字时保留必要滚动，不裁切操作控件。
- 模式卡片、关卡和字块使用轻微厚度与按压反馈，进度采用徽章样式，棋盘采用淡点阵底纹。错误与过关使用短动画，系统偏好减少动画时关闭动效；不增加解释文字或新的游戏机制。
- 界面正文及按钮统一为 16–18px，辅助标记 14–16px，关卡数字及进度 18–22px，标题 22–26px。题面汉字随棋盘适度缩放，输入字与题面字采用相同字号，限制最大字号以避免失衡。
- 答题操作区的反馈和主按钮使用 18–22px，反馈与按钮之间至少间隔 14px。棋盘占据剩余空间并居中，操作区固定在面板内部下方；矮横屏仍放在棋盘右侧。
- 提交按钮最小高度 64px；手机宽度铺满操作区、文字 20px，桌面最大宽度 440px。过关进度占位保持相同高度，切换状态时不挤动棋盘。
- 横竖屏返回按钮直径均为 64px，采用深绿底与 32px 浅色箭头；分页控件高度至少 52px。上一关、重玩入口至少 44px，提交按钮至少 64px、文字 20–22px，关卡数字至少 20px。手机竖屏网格采用 3–5 列，宽屏允许更多列，但均按每行至少约 72px 计算分页；横屏通过减少行数适配高度，不缩小按钮。
- 铜钱标志采用圆形方孔图案，页面标志及标签页图标均沿用页面的深绿与浅绿配色，不使用铜金色；入口指示采用向右的 SVG 尖括号。
- 许可署名随公开文件保留在 `NOTICE.txt`，游戏页面不展示来源说明。

## 组织与发布

本项目专属页面、题集、工具、测试和文档集中在 `word-kanji/` 内。普通网站从 `public/` 白名单打包，映射至网址 `/puzzle/word-kanji/`；Toy 从公开资源与 `toy/` 专属模块白名单组装独立产物，不直接上传源码目录。预览服务位于 `word-kanji/scripts/serve.py`，对应测试也在项目的 `tests/` 内；不在根目录提前提取工具。私有题库在仓库外。
