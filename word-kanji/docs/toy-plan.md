# Toy 版本计划

2026-10-05 最新调整：Toy 仅保留一字、二字闯关，首页直接选择题型，不发布无尽模式、生成器或扩展词库；闯关采用独立审核筛选，目前为 583 / 310 题。原网页版保持原样（586 / 311 题、`endless-v1` 及原存档）。两端进度不互通。详见 [词库与版本隔离](vocabulary-policy.md)。

日期：2026-10-05。状态：按用户要求收缩为纯闯关版本；本轮仅修改本地代码，未代为上传或提交审核。本文同时记录已确认需求、当前实现默认和后续范围。

用户明确要求先看效果、暂不发布。当前仅提供本地预览，不上传预览包或提交平台审核。`scripts/serve_toy.py` 以独立临时目录组装页面，明确标示云存档和榜单为内存模拟数据，不使用真实账号或平台接口；演示 SDK 不进入发布白名单。

本地预览现提供每榜 100 名模拟玩家（含“本地体验（我）”），用于查看长榜滚动和个人成绩展示。一字模拟成绩 268、二字 196；这些成绩仅为演示榜单数据，不伪造实际关卡通过记录，不包含题目解答，不进入发布包。

## 用户已明确的方向

- 为 word-kanji 提供 Toy 版本，同时保留当前网站版本。
- 希望引入云存档、排行榜等平台特色功能；先规划，再确定实施范围。
- 仅保留一字、二字闯关。首页直接选择这两个题型，进入闯关选关页；无尽入口、生成逻辑、词库与排行榜均退出 Toy 发布包。
- 一字与二字分别排名，共两个闯关榜，不采用通过数相加的总榜。
- 每榜按实际通过数降序排列；通过数相同时，越早达成该通过数的玩家排名越高。
- Toy 版只支持 Toy 平台内存档，不与原网站互通，不保留文本存档码的导入、导出或备份机制。原网站保留现有存档机制。
- 云存档自动工作：进入自动读取、过关自动保存，不要求玩家点击连接或手动保存。仅在异常时提示并提供重试。
- Toy 版右上角的原存档按钮替换为排行榜图标，与帮助按钮并排；云存档状态常驻右上角。首页不再单独放置排行榜或存档入口，普通网站仍保留原存档按钮。
- 排行榜弹窗不展示“通过数越多排名越高”等排序与离线上报说明段落，将空间留给榜单；排名规则保持不变，详细口径保留在本文。
- 玩家较多时采用分页，个人成绩固定在列表上方。每页人数随可用高度调整，使用上一页／下一页和页码导航，常见手机、横屏及桌面尺寸不依靠榜单滚动条；极小窗口或大字号保留必要滚动，不裁切操作。
- 用户确认不做总人数及排名百分比功能，保持个人名次、通过数和前 100 名分页榜单；本地预览同样不展示总人数或百分比。

除上述明确要求外，以下架构、其他榜单规则和阶段划分均为当前建议，不代表用户已确认。

## 现状与平台依据

普通网站为原生 HTML/CSS/JavaScript，采用相对资源路径和 hash 导航。一字 586 题、二字 311 题，保留本地进度、文本存档码和同题集进度并集合并。Toy 独立产物已接入云存档和排行榜。普通网站的文本码校验不是身份认证，也不是防作弊措施。

B 站官方 Toy 仓库的[内容检查清单](https://github.com/bilibili/toy/blob/main/skills/toy/references/content-checklist.md)列出 getCloudStorage、setCloudStorage、removeCloudStorage、submitScore、getRankList、getMyRank。其说明指出排行榜仅更新更高成绩、接口额度由同一个 Toy 的玩家共享，要求批量调用、缓存读取、事件触发和限流退避。

2026-10-02 直接读取[官方 SDK](https://s1.hdslb.com/bfs/seed/toy/app/sdk/toy-sdk.js)确认：submitScore、getRankList、getMyRank 均接收 board 参数；SDK 校验其为 1–5 的整数，省略时默认 1。因此当前 SDK 提供五个榜位，可为一字、二字分别指定榜位；实际宿主中的写入与读取隔离仍需联调验收。

后续成功读取[官方发布指南](https://www.bilibili.com/toy/publish/guide)加载的文档资源（文档日期 2026-09-09）：SDK 挂载在 window.toy；云存储按账号与 Toy 隔离，只要求登录，不触发用户资料确认，同 key 覆盖，每值最多 1024 字节。排行榜支持 all/month/week/day，按分数降序、同分先达成者优先，名次唯一；首次上榜的平台资料确认与云存档独立。当前不调用 getUserProfile，不依赖 toyOpenId 或昵称。官方类型注释仍有“1/2/3”旧表述，能力参数说明及实际 SDK 校验已为 1–5；本项目现仅使用 1、2；不访问 3、4 的历史无尽成绩。

当前尚未找到本机 toy CLI。真实宿主的登录与首次上榜确认、云存档与榜单读写、预览和正式数据是否隔离仍需发布前联调。覆盖式云 KV 无条件更新接口，跨设备严格一致性不作保证。

## 阶段一：能力验证与双版本结构

1. 准备官方 CLI 与 SDK 文档，用最小测试页验证登录、云存档读写、成绩提交和榜单读取。只使用人工测试数据，避免测试成绩污染正式榜。
2. 在 word-kanji 内复用公开样式、题面模板、图标与进度纯逻辑；Toy 独立维护 toy/app.js 的闯关控制器和 toy/home.html 首页，避免修改原网页版。
3. 已实现：普通网页继续使用 public/ 及现有 Pages 工作流；Toy 专属模块、弹窗片段与样式放 toy/，由 scripts/build_toy.py 白名单组装至独立输出目录。public/progress.js 复用进度纯逻辑，普通网站 platform.js 为空适配；Toy 打包替换控制器、首页和适配模块，不打包 save-code.js 或任何 endless* 资源；构建读取通用词库仅用于内存中的闯关审查。
4. 普通网页不加载 Toy SDK。Toy SDK 不可用、未登录或断网时允许本地游玩，平台功能给出明确状态。
5. 同时验证 /puzzle/word-kanji/ 与 /toy/<slug>/index.html 的访问、刷新、hash 导航及资源加载。只发布前端白名单文件。

## 阶段二：云存档（建议首版优先）

- 闯关沿用 revision、completed、pending 及协议版本 v=1；保留原闯关云键。旧无尽云记录不读取、不写入、不删除。题集未变则沿用 revision 和进度，不为移除入口重置闯关。不保存填字、正确答案、完整组词或解题过程。
- 已实现自动初始化：页面每次打开直接读取平台云存档，不读取旧的手动连接开关、不请求用户资料。初始化期间暂缓游戏操作，防止云进度覆盖刚输入的状态；失败后恢复操作并明确显示未保存风险，未登录提示先登录 B站。网络恢复或页面返回前台自动重试；网络失败有限次数指数退避。移除云存档弹窗；右上角按钮下方常驻紧凑状态“云存档 · 读取中／已保存／待同步／需登录”，详细原因保留在悬浮提示及无障碍名称中，异常时同处显示重试入口。当前默认两枚图标横向排列、状态另起一行，各页面预留顶部高度，避免与返回按钮或题目重叠。
- 为隔离本机待重试缓存，在当前账号的 Toy 云空间保存随机 128 位标记 `wk_scope_v1`，它不是账号 ID 或鉴权凭据。平台负责账号隔离；本地缓存使用 `word-kanji:toy:auto-v1:<标记>`，只有成功读取相同云端标记后才合并。闯关同题集按已通过关卡并集合并；云端格式或版本不符时不覆盖原存档，不实现通用跨题集迁移。不读取初版手动连接方案的本地缓存。
- 本地写入先完成，再在新过关事件启动异步同步，不阻塞 900ms 自动切关。云端按题型和题集版本设置独立 key，批量读写；正在同步期间新增进度会在后续一轮提交。同步先读取并合并，再写云存档、提交提升后的成绩，避免榜单故障阻止存档写入。重复过关不重复提交。联网恢复、返回前台和手动同步也可触发检查；不依赖关闭页面请求。
- 保留待同步状态；网络或限流错误使用指数退避与随机抖动，最多自动重试五次，再由手动同步或后续事件重试。冷却期间手动点击不会绕过退避。授权失效与数据损坏不自动重试。显示同步状态和失败提示，不提供文本备份或存档码入口。
- 同步读取和写入前核对云标记，发现标记变化时丢弃旧会话响应、停止旧待写队列并自动重新读取当前账号存档。初次两设备同时建立标记可能竞争，采取重新读取、不盲目合并的保守策略。SDK 没有绑定账号的事务写入，因此无法保证恰在请求执行期间切号的严格原子性；不宣称此机制是身份认证。未登录试玩仅保留会话状态、不入榜，登录后恢复平台存档，不合并游客试玩进度。
- 核实 SDK 是否支持条件写入/版本控制；若仅支持覆盖式 KV，读后合并仍有跨设备竞争，不能承诺强一致或绝不丢进度。保留设备本地副本，设计重连合并与冲突测试。
- 原网站与 Toy 存档完全独立，不做自动同步或手动互通。Toy 页面移除存档码导入、导出、复制、粘贴恢复及相关提示，不提供隐藏导入接口；原网站继续保留现有文本码功能。可复用进度校验、合并等纯逻辑，但 Toy 不接入存档码编解码流程。

## 阶段三：排行榜（建议首版做休闲进度榜）

- 一字、二字两个独立闯关榜，按实际通过数降序、同分首次达成时间升序排名；重复过关不加分，不重复提交相同成绩。
- 已按官方同分规则接入平台排序，列表顺序和个人排名均使用平台返回值，不在本地重排。当前实现默认以服务端接收成绩的先后作为达成时间口径；离线或网络延迟后的补交不会回填客户端时间。按用户要求，弹窗不再展示这段规则说明，口径保留在本文。该网络时间口径为实现默认，不代表用户曾明确要求；真实宿主的最终同分顺序仍待联调。
- board 1 为一字闯关榜，board 2 为二字闯关榜，使用 all 永久榜。仅两个按钮切换，各自缓存前 100 名并按可用空间分页，我的排名独立展示。翻页不增加请求；恢复时先读取平台已有成绩，保留达成时间。历史无尽榜位 3、4 不再请求或提交，平台残留数据不由本地改动删除。
- 题集变更时评估榜单版本隔离，防止不同总题量混排；五个榜位不意味着支持任意多赛季或每日重置，不预先承诺每日榜。
- 两个榜单只统计 Toy 版对应账号的通过数；恢复同一账号的 Toy 云存档不重复加分，不重置已有成绩的达成时间。
- 云端进度保存先于成绩提交；拒绝上榜资料确认会暂停本次会话上榜，不影响后续自动云存档。下次打开可重新尝试上榜，云存档本身始终不请求昵称或头像授权。
- 排行榜按需打开、缓存结果、手动刷新，错误后限制再次刷新频率；不轮询。账号切换清空个人排名缓存；云同步变化使榜单缓存失效。
- 当前官方 getRankList 返回前 N 名数组，getMyRank 返回 ranked/rank/score，未提供总上榜人数。按用户确认取消人数与百分比功能，相关适配模块及模拟人数接口已移除；不展示“暂不可用”占位，不将前 100 名误当成总人数。
- 当前展示平台返回的昵称、排名和通过数，不加载头像；不把身份或 SDK 凭据写入公开资源。
- 静态判题和客户端上报只能支持休闲展示，移除存档码也不构成防篡改保证，不能据此宣称公平竞技。不能上传正确输入作为成绩凭据。强竞技需要另行评估可信服务端校验和平台支持。

## 后续候选功能

- 每日挑战：每天同一组题，挑战成绩与闯关存档分离；先确认日期依据、挑战/榜单分区和重置能力。仅支持历史最高分的单榜不能直接实现每日榜。
- 成就：按通过数量设置里程碑，在游戏内计算并随存档同步；不预设 Toy 有原生成就接口。
- 成绩分享：只展示数量、挑战成绩和入口，不展示真实题目的明文解答。
- 视频联动：发布后可按用户指定绑定自有视频；本次不执行绑定。
