# 一字标准型难度评定

本页的一字模型保持不变。二字筛选采用六项方向计数扩展，排序使用独立的两步最优顺序模型，详见[二字难度](two-difficulty.md)及[二字题库生成](two-standard-count.md)。

当前模型：`broad-directional-word-count-lexicographic-v2`。

## 计数范围

使用本地 HSK 全等级（含 7–9）与 CC-CEDICT 的二字汉字词并集，按词的字面去重。不同义项、重复来源不重复计数，一字词和三字以上词不参与。包括扩展词库里的生僻词和专名，不按出题等级、答案允许字域或题面互异性额外过滤。

当前计数词库包含 60,383 个不同二字词。

实际出题仍只使用 HSK 词汇；扩展词库用于难度计数和唯一性审查。数据版本由 `data/manifest.json` 及题库概要中的来源哈希记录，不在线查询浮动词库。

## 四项难度序列

设题面上、左、下、右四字为 `T、L、B、R`：

- `首(c)`：扩展二字词库中，以 `c` 开头的不同词数。
- `尾(c)`：扩展二字词库中，以 `c` 结尾的不同词数。
- 先求 `首(T)、首(L)、尾(B)、尾(R)`，再将这四个整数从小到大排列。

得到的四项序列按字典序比较：先比较最小项，相同时比较第二项，再比较第三、第四项。序列越大越难。**不比较总和或平均值，也不使用 HSK 等级作为难度或同分决胜依据。**

例如计数序列 `(5,5,5,5)` 比 `(1,90,90,90)` 难；`(5,5,5,6)` 又比 `(5,5,5,5)` 难。这只是计数示例，不对应真实题面或答案。

交换两个入字或交换两个出字不会改变序列；入字和出字身份交换后须重新按方向计数。

## 筛选与编排

1. 从完整一字题库的 4,071,532 个规范题目代表重新开始，不在旧筛选结果上继续删选。
2. 对每个答案，按难度序列降序选择；序列相同则优先原始题目编号较小的题目。
3. 每个答案只保留最难的一题，其余候选全部排除。这是关卡筛选限制，不属于良好题目的标准；不同答案仍允许复用线索词。
4. 对筛选结果按难度序列升序编排关卡。答案不再重复，无需同答案间隔，也不再因此出现局部难度回落。

当前私有筛选结果为 **587 道题、587 个答案字**。网页从中移出一道作为帮助例题，实际发布 **586 关**，后续导出同样排除教学题。此前 1,408 题的字典序去重版、旧等级优先版和中间求和版均未覆盖，保留在仓库外。

结果概要见 [筛选统计](../datasets/one-standard-hsk-hardest.summary.json)，全部候选的最难题比较与逐题唯一性复核见 [验证报告](../datasets/one-standard-hsk-hardest.validation.json)。

## 数据与复现

```powershell
python -X utf8 word-kanji/scripts/select_one.py --one-per-answer
python -X utf8 word-kanji/scripts/validate_selection.py
python -X utf8 word-kanji/scripts/export_campaign.py
```

新私有文件为 `one-standard-hsk-hardest.sqlite`。已有文件不覆盖，可通过 `--output` 另指定仓库外路径；验证时通过 `--selected`、导出时通过 `--source` 选择对应私有文件。不带 `--one-per-answer` 的筛选命令仍保留旧版同答案线索词不重复策略。

公开 `campaign.json` 中的 `difficulty` 是四个升序整数的数组，不含答案或完整组词。旧公开版本的标量格式仅在历史审计中兼容。题目等级字段继续保留。私有 `selection_trace.priority` 以大于单项最大计数的基数编码四项序列，保持字典序；该编码不进入前端。

更换题库会更新题集版本，因此旧版闯关进度自动从头开始。
